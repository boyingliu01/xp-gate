# Definition of Done（统一完成定义）

一个 REQ 只有在**全部 10 项**都可指向证据时才算完成。这份清单是 #607 的落地，
对应指南 §12；它存在的理由是本仓库历史上反复出现「以为完成了，其实没有」：

- **#561** 覆盖率阈值形状写错（`Path` 而非 `Partial<Record>`），声明 80% 但整个门禁是空转
- **#570** 覆盖率检查 fail-open，跑不起来时报告通过
- **#585** Gate 5c 静默通过
- **.xp-gate/modules 陈旧副本**（2026-10-19）劫持 Gate 6 数周，hook 报的警告数和独立扫描永远对不上

共同点全部是：**某一步从未真正执行，而没有任何东西把这件事说出来。**
所以这份清单里每一项的判据都是「证据在哪儿」，不是「做没做」。

---

## 10 项完成定义

| # | 条目 | 判据（必须能指出位置） |
|---|------|------------------------|
| 1 | **需求可追溯** | `specification.yaml` 有 REQ + AC；测试文件带 `@covers AC-xxx`；`scripts/__tests__/ac-reference-guard.test.cjs` 通过 |
| 2 | **测试先行** | 实现前存在失败的测试；或说明为何不适用（纯文档/配置） |
| 3 | **测试真的能失败** | 至少一个变异体/破坏被测试抓住。「测试通过」在从未运行时和「功能正确」无法区分 |
| 4 | **验证命令已运行** | 记录实际命令与输出，不是「应该是绿的」。CI 命令与本地命令一致 |
| 5 | **门禁未降级** | 无 `--no-verify`；无新增基线额度来吸收本次改动自身的告警 |
| 6 | **镜像已同步** | 改了 `githooks/`/`skills/`/`plugins/` → `bash scripts/check-hook-mirror.sh` 输出 PASS |
| 7 | **不做未经要求的相邻改动** | 每行改动可追溯到本 REQ；顺手发现的无关死代码只提及不删除 |
| 8 | **已知限制已写明** | 没做的部分、以及为什么没做，写进 issue/提交，而不是留空 |
| 9 | **文档与实现一致** | 门禁数量、CLI 表、阈值等出现在多处的事实同步更新（见 `AGENTS.md` "Known Drift"） |
| 10 | **可回滚** | 提交粒度单一；出问题时能单独 revert 而不牵连其他改动 |

## 相位落点

- **Phase 4 VERIFY**：逐项过 1/2/3/4/5/6，任何一项拿不出证据 → 不得进入 SHIP。
- **Phase 5 SHIP**：逐项过 7/8/9/10，然后才推送。
- **Phase 6 CLOSE**：把第 8 项「已知限制」回填到 issue 并关闭。

## 常见误判

| 看起来完成了 | 实际没有 |
|---|---|
| 「测试通过」 | 没跑过会失败的版本，不知道它能不能失败 |
| 「门禁有配置」 | 配置形状错/键名不对时被静默丢弃，等于没有（#561） |
| 「工具缺失时跳过」 | 跳过被当成通过；只有 Gate 8 是 fail-closed |
| 「CI 绿了」 | CI 可能没跑到那一步（`if:` 条件不满足），或跑的是旧副本（#451） |
| 「注释写了这么做」 | 注释与代码漂移；只有测试能固定行为 |

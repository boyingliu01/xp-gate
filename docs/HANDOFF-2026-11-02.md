## 二、这个项目的核心特征（读这一节能省掉大量返工）

### 2.1 贯穿全部缺陷的同一个模式

本会话关闭的 5 个 issue、以及几乎全部 29 个 open issue，都属于同一个族：

> **一个从不失败的检测器，与「没有漂移」无法区分。**

具体表现（这 5 种在本仓库都实际发生过，不是假设）：

| 表现 | 实例 |
|---|---|
| 检测器从未启动 | #686：`architecture.yaml` 从未传给 archlint，分层规则自始至终没生效过 |
| 检测器恒假 | #704：返工率恒为 0，「0% 返工」与「无法测量」不可区分 |
| 检测器静默丢弃对象 | #702：`.java` 测试文件被直接跳过，覆盖率绿得毫无依据 |
| 检测器自身的证据被污染 | #710：门禁阻断了自己写出的 JSON 报告 |
| 检测器成功但结果为空 | pre-push 审计记录 `reason` 被 shell 引号吃成空串，**看起来正常生成，内容却是空的** |

**交接要点**：修 bug 时先问「这个检测器真的会失败吗」，再问「它失败时我们能看到原因吗」。写测试时，**必须做变异验证**（见 §4.3），否则很可能写出恒真守卫。

### 2.2 架构事实

- `VERSION` 是唯一真源（4 位 `MAJOR.MINOR.PATCH.MICRO`），`node scripts/sync-version.cjs` 传播到 package.json（3 位）和 73 个 AGENTS.md 头。**永不手改 package.json 版本**。
- 发布是 push 触发的：`.github/workflows/npm-publish.yml`。push 到 main 即发布。
- `githooks/` 是钩子真源。`core.hooksPath` 当前指向 `D:/projects/xp-gate/githooks`（**改了就生效，无需同步**）。
- 镜像对：`githooks/adapters`、`githooks/lib`、`src/principles`、`src/build-integrity`、`skills` 都有副本，用 `xp-gate sync-mirrors` 检查/修复。
- 规格源：`specification.yaml`，结构是 `specification.requirements[]`（**4 格缩进**），`id: REQ-686` 这种格式**不带语言前缀**。当前 152 个 REQ。
- `scripts/__tests__/ac-reference-guard.test.cjs` 会扫描所有 tracked 源码里的 `AC-XXX-NN` 字面量。**测试夹具里的假 AC id 必须运行时拼接**：
  ```js

  const FIXTURE_AC = 'AC-FIXTURE-01-01';                    // ❌ 守卫会红
  ```

### 3.1 环境上已踩过的坑（照做，别重蹈）

| 坑 | 正确做法 |
|---|---|
| `node_modules` 有 `.bin/*.cmd` 包装，`ls node_modules/.bin/vitest` 可能找不到 | 用 `-e node_modules/.bin/vitest -o -e node_modules/.bin/vitest.cmd` 判断，或直接 `npx vitest --version` 验证 |
| `find package-lock.json -newer node_modules/.package-lock.json` 判「需重装」 | **方向反了**。node_modules 比 lock 新才是健康状态 |
| 用 `/tmp/xxx` 路径给 node 脚本 | node 会解析成 `D:\tmp\xxx`。**用仓库相对路径** |
| `git commit -F /dev/stdin <<EOF` | 报 `could not read log file`。**先写 `/tmp/msg.txt` 再 `-F`** |
| `git rev-parse --abbrev-ref HEAD` 在空仓库/分离 HEAD 下会**先打印 `HEAD` 再非 0 退出** | `$(cmd \|\| echo "fallback")` 会得到两行。**必须「先捕获再判空」**（这正是 #710） |
| node 改写过钩子文件产生 CRLF | 用 `'latin1'` 读、`\r\n`→`\n` 写回 |
| `git status` 显示幽灵 `M` 但 `git diff` 为空 | 直接 `git add` 即可清除 |
| api.github.com 频繁 TLS 超时 | `gh` 调用包重试循环，JSON 先写仓库相对文件再解析 |

## 四、开发纪律（本项目的硬约束）

### 4.1 绝不做的事

- **绝不用 `--no-verify`**。`githooks/QUALITY-GATES-CODE-OF-CONDUCT.md` 明确这是流程违规。
- 绝不手工编辑 `package.json` 版本、绝不直接改 `src/npm-package/adapters/`（改 `githooks/adapters/` 后同步）、绝不改 `src/npm-package/plugins/*/src/`（真源在 `plugins/<name>/src/`）。
- 不给 `.warnings-baseline.json` 加新条目（必须保持 12 条）。
- 不给 `src/npm-package/` 加运行时依赖（零安装是产品承诺）。

### 4.2 TDD 是强制的

先写失败测试 → 再实现 → 再重构。测试文件必须带 JSDoc 标签：
```ts
/**
 * @test REQ-XXX
 * @intent 为什么这个测试存在
 * @covers AC-XXX-NN
 */
```

### 4.3 变异验证（本会话最重要的经验）

**一个从不失败的测试，与没有测试无法区分。** 每个新测试都要验证它在 bug 存在时会红：

1. 只改**判断**（`if (false) {`、换掉字面量），**不改控制流**。
2. `grep -c` 确认变异真的写进去了。
3. 跑测试，**确认它变红**，而且红在预期的断言上。
4. 还原，确认变绿。

本会话靠这一步抓出两个恒真守卫：
- 测试用了不存在的 `$run_output`（bats 的变量是 **`$output`**），判断恒假、永远绿色。
- sed 版转义器被多层 shell 引号吃坏，`2>/dev/null` 让错误消失，`reason` 变成空串。

### 4.4 提交与发布

```bash
# 提交（先写消息文件）
cat > /tmp/msg.txt <<'MSGEOF'
fix(scope): 一句话说清「修好了什么」而不只是「改了什么」

正文解释「为什么」——尤其要写清这个缺陷在什么条件下会伤人。
MSGEOF
git commit -F /tmp/msg.txt

# 发布
echo "0.35.23.0" > VERSION
node scripts/sync-version.cjs        # 刷新 73 个 AGENTS.md 头
# 加 CHANGELOG 条目
git add -A && git commit -F /tmp/msg2.txt
git push origin main                 # 触发 npm-publish
```

**发布后必须验证**（不能只看 CI 绿）：
```bash
npm view @boyingliu01/xp-gate version   # 确认新版本号
# 并且实测包内容真的含修复
```

### 4.5 门禁相关的操作要点

- **Gate 11（Sprint Flow）** 需要 `.sprint-state/delphi-reviewed.json` 且 `verdict: "APPROVED"`。
- **Gate 12** 是 warning-only，但读自己写的 JSON；若报告损坏会 BLOCK（#710 就是这个）。
- 这三个 gate 在 push 到 main 时会**跳过**（设计如此）：Gate ML、Gate UI、Gate MW。

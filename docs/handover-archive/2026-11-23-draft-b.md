### 2.3 WSL 特有的坑（这是本次迁移最大的风险）

| 坑 | 说明 | 检查 |
|---|---|---|
| **`/mnt/c` 下的 Windows 二进制** | 在 WSL 里 `which checkov` 可能选中 `/mnt/c/...` 的 Windows shim，`--version` 能过但真实扫描 `exec` 失败（126） | `which checkov` 必须是 `/usr/...` |
| **混合文件系统** | 仓库放在 `/mnt/c/...` 会有 CRLF、权限、大小写、inotify 全部失效 | **仓库必须在 Linux 原生路径（`~/`）** |
| **换行符** | `.gitattributes` 已配置，但 WSL 与 Windows 交替提交可能触发 Gate MP 误报（#824） | `git config core.autocrlf` 应为 `input` 或 `false` |
| **`$HOME` 变化** | `~/.config/xp-gate` 在 WSL 是全新的空目录，不是 Windows 那份 | 重装，不要 cp 过来 |

- [ ] 仓库在 `~/` 下，不在 `/mnt/c`
- [ ] `which <每个门禁工具>` 全部指向 `/usr` 或 `~/.local`，没有 `/mnt/c`

## 7. 坑清单（WSL 侧仍然适用）

### 7.1 门禁编号是标签，不是身份
`githooks/gate-registry.sh` 是唯一真相源。编号只是位置。
历史上曾把 Gate 9 写成 SAST（实际是 Build Integrity），导致一次修复写进了从不被引用的文件——
**改了等于没改，但看起来已落地**。看到门禁编号先查 registry。

### 7.2 镜像树：改错地方会被静默回滚
canonical 在左，**永远改左边**：
- `githooks/adapters/` ↔ `src/npm-package/adapters/`
- `githooks/lib/` ↔ `src/npm-package/hooks/lib/`
- `skills/` ↔ `src/npm-package/skills/`
- `plugins/*/src/` ↔ `src/npm-package/plugins/*/src/`

改完跑 `node src/npm-package/scripts/sync-package-content.js`。
手改镜像会在下一次 prepack 被覆盖（v0.27.3 正是这样漏发的）。

### 7.3 提交会自动升版本
`package.json` 的 `prepare` 钩子（`sync-version.cjs`）在提交时**自动把 VERSION 抬一位**并刷新所有清单。
这是设计行为，不是 bug。但它意味着**一次文档提交也会动 VERSION 和 7 个清单文件**。
commit 时若看到 30+ 文件变更，先确认是它干的。

### 7.4 `core.hooksPath` 意味着你的编辑可能无效
全局安装时 git 跑的是 `~/.config/xp-gate/hooks/`，不是仓库里的 `githooks/`。
改完跑 `xp-gate doctor --sync-hooks`，否则**改了一点效果都没有**。

### 7.5 陈旧 adapter 会盖掉新版本
`githooks/adapters/*.sh` 走三级解析，`~/.config/xp-gate/adapters/<lang>.sh` 可能比仓库里的旧。
**hook 与直接调用结果不一致时，先 `md5sum` 两份再怀疑代码。**

### 7.6 永远不要 `--no-verify`
违反 `githooks/QUALITY-GATES-CODE-OF-CONDUCT.md`。

## 8. Windows 专有坑（迁过去自动消失，但别在 WSL 重现）

| 坑 | 曾经怎么绕的 |
|---|---|
| `npx lizard` 报 `could not determine executable` | 用 `python -m lizard` |
| `Edit`/`npx tsx` 偶发 `spawn EPERM` | **编辑其实已生效**，用 grep/tsc 验证而不是重试 |
| `find / -name`、`python -m venv` 挂起 >600s | 避免使用 |
| Git Bash 的 `/d/...` 在 Node `writeFileSync` 里解析错 | 用 `D:/projects/...` |
| bats 全量报 "command line is too long" | Windows 命令行长度限制，CI 分批跑 |
| `git stash` 因 `.git/index.lock` **静默失败** | 用手工 `git show HEAD:<path>` 存基线再 `cp`，每次替换后 grep 标记确认版本 |

> 最后一条在 WSL 上风险低但仍存在：并发 git 操作（多 agent）会留下 `index.lock`。
> 本次交接时就撞到一次——一个并发提交把我暂存的文件连带提交了，提交信息与内容不匹配。
> **多个 agent 同时动同一个仓库时，提交前先 `git status` 确认暂存区只有你的文件。**

## 3. 本仓库的踩坑记录（血泪版）

这一节是本文档最有价值的部分。每条都对应一次真实的弯路。

### 3.1 两个门禁会在同一个函数上互相矛盾

我遇到的具体案例：`gitStatus` 同时被 Gate 6 和 Gate 3 管：

- **Gate 6（Boy Scout）**：`spawnSync` 必须有 `try/catch`
- **Gate 3（复杂度棘轮）**：`gitStatus` 的 CCN 必须 = 1，而 `try/catch` 会让它变成 2

加上 `try/catch` 阻断 Gate 3，去掉它阻断 Gate 6。**两条门禁都没错**，是这个函数承担了两个职责。

**解法是拆函数，不是刷基线**：
- `runGitStatus` 负责启动进程 + `try/catch`（CCN=2，新函数无预算约束）
- `gitStatus` 保持无分支（CCN=1）

门禁会贴心地提示"可以刷新基线通过"。**别信这个建议**——那等于用永久豁免换掉一次五行拆分。

### 3.2 shellcheck 基线是空的，任何警告都算"新增"

Gate 1 曾因 `python.sh:33` 阻断我的提交，而那行**我根本没碰**。原因是 `.xp-gate/lint-baseline.json` 记录 **0 个条目**，所以任何暂存文件里的警告都被判为新增。

修掉它（`[ -n "$(...)" ]` → `grep -q`），**不要写进基线**。并在四种情形验证等价：有目标文件、空目录、路径不存在、单文件。

### 3.3 提交说明里不要写 `# shellcheck` 开头的行

我在 shell 注释里写 `# shellcheck SC2143: ...` 当说明，结果 shellcheck **把它当指令解析**，报了三层语法错误。改写措辞即可。

### 3.4 "测量方法错了" ≠ "产品坏了"

验证 worktree guard 时，我写 `.guard-violation.tmp` 当探针，看到没报警就断定"是我引入了回归"，开始翻 diff 找 bug。

**实际是我的测量错了**：`.tmp` 被 gitignore，`git status --porcelain` 对忽略路径一无所知。查 `snapshotStatus` 输出就能发现它在**两个快照里都不存在**。

按 `~/.dsh/AGENTS.md` 硬规则 1：**先读被测物的调用契约，再设计测法**。我当时跳过了这一步。

### 3.5 并行工作流会偷走你的变更集

Gate 5 有两个分支：

- `Changed files:` 为空 → 判为"只有文档改动"→ **跳过测试，报 SKIP**
- 有代码文件 → 真跑测试

我提交时遇到过两次 `Changed files: ` 为空，**原因是另一个任务在我 `git add` 之后、门禁运行之前提交了**。结果：Gate 5 跳过，但提交成功。

**后果**：那一次提交的代码**没有经过本机测试验证**。我手动补跑了确认（37/37）。在 WSL 上如果还有并行工作流，**每次提交后手动确认测试真的跑过**，别信 Gate 5 的 SKIP。

### 3.6 版本号不由你控制

`VERSION` 从我开始工作时的 `0.38.77.0` 被别的任务推到了 `0.38.125.0`。**不要手改版本号**，manifest 由它生成。

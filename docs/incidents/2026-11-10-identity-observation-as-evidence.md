# 把恒等观测当证据 — 一次「实测发现」如何差点进入交付

**日期**：2026-11-10
**场景**：sprint-20261110-33（P1-C 架构整改）设计阶段
**关联设计**：`docs/plans/2026-11-10-resolve-p1c-design.md` §3.4 / §5.8 / §5.9
**缺陷类别**：验证方法失效（与本次要修的缺陷同构）

## 一句话

我声称「实测发现」了一条关于 archlint 行为的结论，并据此改了设计。
那条结论是错的——因为我的观测方法**无论底层真相如何都返回同一个值**。
它能区分的前提从未成立过。

## 事实经过

设计「`xp-gate init` 该生成什么样的 `.archlint.yaml`」时，我在两个 fixture 里
放了完全不同的配置，然后运行：

```
$ npx archlint detectors list
13 detectors ✅ enabled by default
18 detectors ❌ disabled by default
```

两次都返回 13。我把它读作「默认集被保留」，进而推断：

> 写 2 条 `enabled: true` 规则会关掉另外 11 个默认检测器。

然后我把这个推断写成了「实测反转」，做成对比表格提交给 Delphi 评审。
**R2 第 2 轮，两位专家接受了这个论证并在此基础上评审。**

## 真相

第 3 轮有专家质疑「`detectors list` 可能不读项目配置」。我去验证：

| 实验 | `.archlint.yaml` | `files_analyzed` | `cyclic_dependencies` | `total_smells` |
|------|------------------|------------------|----------------------|----------------|
| A | 无配置 | 2 | 1 | 1 |
| B | `rules: {code_clone: {enabled: true}}` | 2 | 1 | 1 |
| C | `rules: {cyclic_dependency: {enabled: false}}` | 2 | **1** | **1** |
| D | `ignore: ["src/b.ts"]` | **2** | **1** | **1** |

15 个 summary 字段逐一对齐，B 与 A **0 差异**。
显式 `enabled: false` 也被静默忽略（C）。`ignore:` 同样被忽略（D）。

**`archlint detectors list` 根本不读项目配置文件。** 我"证明"的那件事，
和这个命令能观测到的任何东西都无关。

## 两个独立的错误

### 错误一：把恒等观测当证据

一个**无论输入怎么变都返回相同值**的观测，对任何假设都没有检验力。
我当时注意到「两次都是 13」，并把它解释为「默认集被保留」——
但同样的观察也完全符合「这个命令不看配置」。我没考虑后一种解释。

**判据**：写下「实测发现 X」之前，先回答
**「我的观测能区分 X 与 not-X 吗？」**
如果不能，那不是实测，是误读。

### 错误二：一步实测当成两步的证明

真实的实测只做了一步：**数出默认启用了 13 个**。
「写规则会关掉另外 11 个」是**第二步**，我从未执行它，却把它并列写成实测结论。

一个论证有两步，只有第一步有数据支撑时，整体的强度等于第一步——
但我给了它第二歩的措辞。

## 为什么这次特别危险

1. **它有表格、有数字、有命令输出。** 形式上完全像真证据。
2. **两位评审专家接受了它。** 论证的说服力掩盖了证据的真空。
3. **它差一点进入 BUILD。** 若照此实现，会交付一个
   `assert(enabledCountWithConfig >= enabledCountWithoutConfig)` 的测试——
   这个断言**永远为真**，因为 `detectors list` 恒返回 13。
   它看起来在守护一条重要不变量，实际什么都没守护。

## 与本次要修的缺陷同构

| 本次要修的缺陷 | 这次我的错误 |
|----------------|--------------|
| 部署清单少了三个文件，但**看起来完整**（因为 `lib/` 靠硬编码装上，掩盖了缺口） | 测试永远通过，但**什么都没验证**（因为观测恒等） |
| pre-push 与 pre-commit 各自解析，**看起来一致** | 论证有实测表格，**看起来有证据** |
| Gate 6 输出 PASSED 而不说明覆盖范围 | 输出 13 而不说明该命令不读配置 |

**共同形态：一个看起来在验证、实际什么都没验证的东西。**
这类缺陷不会报错，只会让人安心——所以它比崩溃更难发现。

## 处置

1. **设计已改**：AC-DEPLOY-003-05 从「计数比较」改为「非平凡守卫 + 正控 + summary 逐字段相等」
2. **加反向断言**：生成模板**不得**包含任何 `rules:` / `ignore:` 键
   （因为实测证明它们无效，写进去就是制造虚假配置）
3. **加前提验证**：实验 E 验证「只有注释的文件」与「无文件」行为一致——
   这是整个模板方案的前提，之前从未验证过
4. **知识改为探测而非断言**：v9 曾把「这些键无效」写成通过条件，
   R2 第 4 轮专家指出那会「只在别人有 bug 时才绿」，archlint 修好后测试变红，
   最终会被当噪音删掉。改为运行时探测 + warning，两种世界都通过

## 顺带发现的真实缺陷

既然 `ignore:` 被静默忽略，**本仓现有 `.archlint.yaml` 里那一大串 `ignore:`
以及 `rules.exclude:` 很可能从未生效**——包括为避开 mirror 副本重复而写的排除项。

若成立，意味着 Code Clone 检测器可能一直在报 mirror 与源文件之间的重复，
而此前的应对是**加更多 ignore**——加在一份不生效的配置里。

**不在本 sprint 处理**，记为设计文档 §7 的后续项（7.1 / 7.2）。

## 可复用的判据

> 写「实测发现」之前：
> 1. 我的观测能区分 X 与 not-X 吗？
> 2. 这个结论是**一次观测**得出的，还是**多次观测对比**得出的？
> 3. 如果结论反过来，我的数据还支持吗？
>
> 三问有一个答不上来，就不是实测。
